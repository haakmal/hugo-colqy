# Colqy hosting contract

Colqy core is independent of hosting. The public site is generated by Hugo; the scholarly citation pipeline uses Pandoc and Python. Hosts only need to execute the **same** build command and publish the resulting `public/` directory.

```sh
python3 -m pip install 'PyYAML>=6.0,<7.0'
python3 tools/build-colqy.py --build --base-url https://your-site.example/
```

**Requirements:** Python 3.12+, Hugo Extended (GitHub Actions currently uses 0.150.0), Pandoc with `--citeproc`, and PyYAML. `bibtexparser` is needed only for the optional CLI importer. The canonical library is `data/references.json` and the generated citation data is derived, not edited by hand.

| Host | Configuration | Notes |
|---|---|---|
| GitHub Pages (default) | `.github/workflows/colqy-pages.yml` | `COLQY_PUBLISH=true` enables publishing; `configure-pages` determines base URL. |
| Cloudflare Pages | Build command above; output `public` | Provide Hugo, Pandoc and Python dependencies in the build environment. Set `--base-url` to the final URL. |
| Netlify / other static hosts | Same command; output `public` | Ensure the build image includes required tools and environment settings. |
| Local development | `python3 tools/serve-colqy-citations.py` | Watches citations and serves Hugo drafts; not a production hosting workflow. |

Sveltia's GitHub backend is separate from hosting. If moving to GitLab or Forgejo, its backend configuration and sign-in method must be adjusted; the content and Hugo/Pandoc build remain portable.

The current GitHub Pages workflow does **not** configure CMS OAuth, edit Hugo defaults, migrate content, or publish drafts. Those are separate release/setup tasks.
